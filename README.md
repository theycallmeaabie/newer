# burnin-screen

AI-driven anomaly detection in component burn-in and screening.
Smart India Hackathon 2026 · Problem statement **26170** (ISRO, Smart Automation, software) ·
Team **SYNTROPIC**.

> **All results in this repository are computed on synthetic data** generated by
> `src/burnin/synth/`. The generator's assumptions are documented in `data/README.md`. Nothing
> here has been validated on real burn-in populations yet. See *Known limitations*.

## What it does

Electronic components are burned in (typically 125 °C, 168 h) and measured at 0 h, 24 h, 96 h and
168 h: standby current `IDDQ`, leakage current `ILEAK`, propagation delay `TPD`. Parts that stay
inside datasheet limits can still carry **latent defects** that show up as behaviour anomalous
*relative to their lot*. This system:

- **Module A — dynamic outlier detection.** Robust per-lot limits (median ± k·σ_robust in log
  space), change-between-readings limits, a robust multivariate check, and lot-level checks that
  tell a tester problem apart from a part problem. A part at 45 µA in a lot whose median is 10 µA
  is flagged even though the datasheet says 50 µA.
- **Module B — drift prediction.** From the 0 h and 24 h readings only, forecast the 168 h value
  with a calibrated interval, and flag for early rejection when the *upper bound* of the drift rate
  exceeds a defined safety slope.
- **Fusion and explanation.** PASS / REVIEW / REJECT at each checkpoint, every non-PASS
  decision carrying reason sentences with numbers, units, the lot reference and the limit.

## Quick start

Requires Python ≥ 3.12 and Node ≥ 20.19. Dependencies are fetched once (pinned in
`requirements.lock` and `web/package-lock.json`); everything afterwards runs offline on a laptop
CPU.

```bash
make setup      # venv + pip install -e ".[dev]" -c requirements.lock + npm ci
make test       # pytest
make lint       # ruff check + ruff format --check
make api        # FastAPI on http://127.0.0.1:8000  (schema at /openapi.json; no CDN-backed /docs)
make web        # Vite dev server on http://127.0.0.1:5173 (proxies /api)
make lock       # regenerate requirements.lock after changing dependencies
```

`scripts/demo.sh` will run the whole pipeline in one command once Phase 7 lands.

## Repository layout

```
configs/           generator.yaml (synthetic data), screening.yaml (k-values, safety slope, costs)
data/              README.md (assumptions, mechanisms, sources), synthetic/ (generated, git-ignored)
src/burnin/        the library: schema, ingest, synth/, module_a/, module_b/, fusion, explain,
                   evaluate, reports
api/               FastAPI application
web/               React + Vite + TypeScript + Tailwind + Recharts dashboard
tests/             pytest suite (includes the no-future-leakage and determinism tests)
scripts/           demo.sh and helpers
notebooks/         EDA only; no core logic
```

Read `CONVENTIONS.md` before contributing: it defines the **leakage rule** (no reading later than
the checkpoint hour may influence a decision), the **units policy**, the robust-statistics policy
and the labels quarantine.

## Known limitations

- **Synthetic data.** Defect shapes and magnitudes are modelled, not measured; sources and open
  TODOs are listed in `data/README.md`.
- **Defects with no 24 h signature** (e.g. step changes after 24 h) cannot be caught at the early
  checkpoint by any method. The evaluation reports 24 h recall with and without them.
- **Small lots** give wide limits; results on lots below the configured size are marked
  *low confidence* and shrunk toward historical lots of the same part number.
